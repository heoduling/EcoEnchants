## 实际修改

`EnchantDisplay.kt` 在当前等级的顶层条件及效果条件都没有显示请求时，跳过 `ItemProvidedHolder` 和两次显示条件查询。实际依赖的 `ConditionBlock.showNotMet` 已包含非空未满足说明行，只有名称标记的条件也包含在内。有显示请求时执行原判断。每次检查当前等级对象，规则变化立即生效。

`EnchantingTableSupport.kt` 在每次预览完成资格过滤后，先读取每个候选的 key，再按 namespace/key 稳定排序。相同 key 保留相对顺序。所有中间数据随本次调用结束释放。

版本号更新到 2026.27-4。构建比较确认 694 个原有 class 字节完全相同，3 个原有 class 的指令发生预期变化，增加 1 个 Kotlin 顶层 helper class。配置默认文件相同，`plugin.yml` 更新版本号。具体清单在 `artifacts.json`。

## 性能实测

最终统计仅取 `final-d`、`final-e` 两次独立 JVM。每个场景、每个版本预热 8 批，测量 12 批，按批交替先后顺序。表格为 24 个批均值的中位数。显示每批 200 次，预览每批 100 次，两版本共 72,000 次实测调用。

物品带 24 行原有 lore、16 项 PDC 字符串和模型数据。显示测试包含物品克隆与 DisplayProperties 构造，使用真实玩家。预览测试包含 Prepare 事件构造和三档结果读取，两版本均通过相同反射入口调用。调用在玩家所属 scheduler 中执行。JVM 最大堆 3 GiB，Java 25.0.3，未独占整台机器。

| 场景 | 旧版 µs/次 | 新版 µs/次 | 本次观察变化 |
|---|---:|---:|---|
| 普通 Bukkit 物品，1 条附魔显示 | 53.825 | 48.476 | 下降 9.94% |
| 原生 Craft 物品，1 条附魔显示 | 40.514 | 38.759 | 下降 4.33% |
| 普通 Bukkit 物品，4 条附魔显示 | 52.153 | 41.896 | 下降 19.67% |
| 原生 Craft 物品，4 条附魔显示 | 53.398 | 42.136 | 下降 21.09% |
| 普通 Bukkit 物品，8 条附魔显示 | 56.952 | 40.328 | 下降 29.19% |
| 原生 Craft 物品，8 条附魔显示 | 58.233 | 44.707 | 下降 23.23% |
| 书本三档预览 | 198.779 | 116.823 | 下降 41.23% |
| 钻石镐三档预览 | 104.957 | 106.066 | 增加 1.06% |
| 钻石剑三档预览 | 147.019 | 131.648 | 下降 10.46% |

钻石镐预览本次测得约慢 1.06%，两次单独中位数也保留在 summary.json。该场景没有测出耗时收益，短测的调度、JIT 和其他工作负载会影响结果。其功能对比通过。

在实际完整显示入口，1、4、8 条无显示条件的自定义附魔，旧版整件物品 hashCode 调用分别为 1、4、8，新版均为 0。有显示条件时仍构造 holder 并计算哈希。

另用平台线程测量 220 个候选的排序子步骤，旧版等价双字段比较算法临时分配中位数为 140432 B/次，新版实际 helper 为 13088 B/次，下降 90.68%。旧算法对照使用相同 key 读取规则，候选是脱离玩家的只读注册表快照。该数据只代表排序步骤。

真实玩家 owner 是虚拟线程，完整显示和 Prepare 的每线程分配计数不可用，记录为 N/A。整服 CPU、MSPT、长期保留内存与生产分配率降幅尚无本轮 A/B 数据。11 月 9 日旧 Spark 中 EcoEnchants 首次入口分配约占 0.586%，不能把局部下降百分比套到整服。
