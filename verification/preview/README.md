## 已修复的行为

- 相同玩家轮次、稳定物品材质和合法候选条件下，名称、耐久、Lore、PDC、模型变化及反复取放不再生成另一组随机提示。玩家物品原数据不被删除或归一化。
- 随机种子使用已有玩家附魔种子和普通书归一后的 Material key；不再加入完整 ItemStack hash 或世界种子。跨世界保持同条件提示稳定。
- 在功能启用时，仅初始化为零的玩家种子；已有非零种子（包括负值）保留。新玩家在打开窗口前初始化，Prepare 的零值保护处理运行时零值。沿用核心 XpSeed 保存及正常付费更新，不新增存储。
- 对过滤后的候选按 namespace/key 排序，稳定候选及品质分组顺序。eco 的 Set.copyOf 集合跨 JVM 随机迭代，重启测试证明仅固定种子仍不足；排序保留候选、总权重及每个候选的权重，不改变合法加权概率分布。
- 取消后不提前丢弃提示缓存，已有取消事件不进入处理；下一次 Prepare 覆盖，玩家退出移除。修复原生窗口中“被取消一次，原位重试却拿到不同于提示的附魔”的原有问题。

生产代码仅修改 `EnchantingTableSupport.kt`，另更新版本为 2026.27-2。未修改 FXEnchant、附魔效果/概率、配置默认值、权限节点、铁砧/磨石、交易、掉落、额外词条抽选或实际收费代码。旧性能优化保留。

## 对脚本的实际作用

在已测试的固定轮次/物品类型/合法候选条件下，原版批量变更元数据可以筛出大量不同提示；最终版80次变更不会比基准多提供一组提示。真实改名和耐久路径也关闭。这能阻断本次确认的低成本预览筛选入口。

脚本仍能像真人一样支付正常经验和青金石附魔，包括用低档正常附魔更新轮次；不同物品类型、权限、书架或合法自定义资格仍按游戏规则计算。此修复没有检测脚本或限制自动点击，没有玩家脚本源码，不能声称阻断全部自动刷附魔或给出整服脚本减少百分比。

## 额外审计与边界

功能、Folia/性能、生命周期三遍审查及独立只读复核未发现重要新增缺陷。新增玩家访问均在现有所属事件上下文；没有新线程、调度器、锁、数据库、按物品/改名次数增长的缓存。当前提示仍每玩家最多一份，退出清理。排序是每次预览对有限候选列表的局部排序；未测整服MSPT或宣称没有任何额外CPU成本。

原生SHIELD测试未得到有效offers，超时记录在 fixed3-extra-console.log；没有证明既有额外物品手动收费分支能从该原生入口触发，所以不能声称额外物品收费已全部通过，也不把条件字节码线索列成已复现漏洞。该分支本次未改。需要覆盖该玩法时，应先取得当前服可正常附魔的准确额外物品/操作入口再复测。

没有验证所有第三方插件组合、所有自定义资格谓词、生产长期运行或并发数百人压力；没有热卸载承诺。JAR仅为本次验证组合的修复交付。
